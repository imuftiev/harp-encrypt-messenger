## Миграции базы данных

Для управления схемой базы данных PostgreSQL используется **Alembic** совместно с **SQLAlchemy**.

Миграции позволяют отслеживать изменения структуры базы данных, применять их и при необходимости откатывать.

### 1. Настройка окружения

Перед выполнением миграций необходимо настроить переменные окружения в файле `.env`:

```dotenv
POSTGRES_USER=postgres
POSTGRES_PASSWORD=your_password
POSTGRES_DB=messenger
DATABASE_HOST=localhost
DATABASE_PORT=5433
```

Убедитесь, что PostgreSQL запущен и доступен по указанному адресу.

### 2. Создание миграции

Для автоматической генерации миграции на основе изменений SQLAlchemy-моделей:

```bash
alembic revision --autogenerate -m "migration_name"
```

Например:

```bash
alembic revision --autogenerate -m "initial_schema"
```

После генерации необходимо проверить содержимое файла в `migrations/versions/`.

### 3. Применение миграций

Применить все миграции до последней версии:

```bash
alembic upgrade head
```

### 4. Откат миграций

Откатить последнюю применённую миграцию:

```bash
alembic downgrade -1
```

Откатить все миграции до начального состояния:

```bash
alembic downgrade base
```

**Внимание:** откат миграций может приводить к удалению таблиц и потере данных.

### 5. Проверка состояния миграций

Посмотреть текущую ревизию базы данных:

```bash
alembic current
```

Посмотреть историю миграций:

```bash
alembic history
```

Проверить наличие изменений моделей, для которых ещё не создана миграция:

```bash
alembic check
```

### 6. Правила работы с миграциями

- Все изменения схемы базы данных выполняются через миграции Alembic.
- Сгенерированные миграции необходимо проверять перед применением.
- Файлы миграций должны сохраняться в Git.
- Названия миграций должны отражать изменения, например `add_message_status` или `create_chats_table`.
- Миграции, уже применённые в общих окружениях, не следует изменять задним числом.
